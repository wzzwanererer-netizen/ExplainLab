# 批准后执行与验收退出

当前执行停在预检。以下为下一阶段的顺序。

| 顺序 | 操作 | 完成条件与证据 |
| --- | --- | --- |
| E0 环境准入 | 复用已有 WSL2 或 Linux VM。核对当前源码、锁与冻结文档 SHA-256。 | 能在 guest 内执行命令，实际记录发行版、内核、ext4/卷、权限、执行身份与对应源包 SHA。Windows 挂载路径不能成为 Linux 测试根。 |
| E1 可安装性 | 在 ext4 验收副本按冻结锁文件安装 Python 依赖，实测关键导入和本地 SQLite。 | 保存 `uv sync --locked`、版本、包与 smoke 退出码。不能完成安装时停止后续运行并记录阻断位置。 |
| E2 PG 准入 | 仅在隔离环境生成测试 DB、测试账号和 DSN，用真实双连接验明身份。 | 两个真实 backend PID、授权角色/库、server_version、端口、迁移 head，实际连接成功。先核对目标再调用会清空测试表的 pytest。 |
| E3 PG B1 | 执行现有 17 项，补其未覆盖的 LCK-07/10、真实预算和释放异常保真。 | 比对 token、TTL、锁投影、DB 行、会话与残留状态。SQL 等待、客户端测试替身和进程终止证据分别登记。 |
| E4 POSIX B1 | 在原生 ext4 上执行存储与 Journal/ProcessLock 平台差异子集，补真实负例。 | 目录根与设备号、inode/hard link、rename/no-clobber、Linux 权限、文件及目录 fsync、同句柄读取、实际锁/终止和恢复结果。 |
| E5 证据复核 | 汇总 PG、POSIX 和可复用 Windows/SQLite 证据。单列 Round 3 新增 DB 祖先链接测试在 Windows 的跳过。 | 必须补 Windows 新路径真机用例时，只跑平台专用最小子集。将已覆盖的 Windows F12、SQLite 计时和冻结通用测试链接到既有记录。 |
| E6 阶段判定 | 按 B1-T01 至 T04 对照报告和失效路径，核对完整性。 | B1 基础项的两环境证据齐全才提交最终裁决。端到端冻结缺口留在 B2/B3/B4/B5。运行失败须区分环境、证据或已复现实现缺陷。 |

E2/E3 和 E4 在 E1 完成后可安排独立运行，且使用不同数据库及临时目录。每次运行写入原始命令、版本、时间、退出码、跳过列表及脱敏日志。不得仅凭整组通绿覆盖冻结矩阵明确但当前套件未执行的行为。

通过条件使用 [冻结路线图](../../plans/V2-A1-04-Batch-B/implementation-roadmap.md) §3 与 [验收矩阵](acceptance-mapping.md)。失败时收集最小证据并停止推进阶段，等待审计裁决。
