# 阶段门槛与剩余风险

| 风险 | 当前裁定 | 真实补测与阶段 |
| --- | --- | --- |
| PG 物理会话、advisory、TTL 与接管 | **B1 阻塞**。冻结路线第 63、73 行及 LCK-10 明确要求真实 PG。IR2-03、04 也需独立复核。 | B1-T03/T04 要求真实实例、双连接、同投影、批获取预算、物理断连及进程结束后的接管。额外核对租约跨过行锁等待后的 GC 写回、心跳退出、原业务异常和连接资源。 |
| POSIX 文件系统 | **B1 阻塞**。故障注入只证明错误传播。 | B1-T01/T02 真实 POSIX 验证根目录、硬链接、不覆盖、目录 fsync、打开句柄后路径更换。实际 crash 后的持久性另按冻结验收层级记录。 |
| GC 文件隔离与进程崩溃 | **B5 验收**。已取得 SQLite LCK-07 的存储租约接管证据。 | GC-07 在隔离后未记录、purge 后未写状态两个切点终止子进程，验证新旧代次和后续 ORP/GC 收敛。跨方言复跑。 |
| TOCTOU | **冻结接受的残余窗口**。失配被观测后必须停止。对已通过最终 verify 至 syscall 之间，不承诺可撤销已经进入的文件变更。 | LCK-08 在最终 verify 的前后分别暂停，并搭配真实文件与接管验证。早期失配防线属于 B1。物理操作整链路证据按 B4 联调和 B5 恢复阶段完成。 |
| SQLite/PG 行为一致性 | **B1 阻塞**。统一检查 owner/token/expiry、预算、失配和事务边界。SQLite 真实库已复现 IR2-01、02。 | PG advisory 存活时 TTL 不允许接管，SQLite 逻辑租约到期可接管。这是冻结差异。须在各自真实库验证跨事务、并发、业务结果保留与错误分类。 |
| GC 人工权限与日志 | **B5 验收**。当前是内部仓库方法。 | GC-11 核对仅授权操作员可触发人工迁移，记录 actor、时间、任务和前后状态，保留文件，避免暴露 HTTP 管理 API。 |
| 原 B1 历史源码 | **审计证据缺口**。当前 13 个 B1 实现及测试文件已审查，首版未形成独立 Git 提交。 | 保留原独立审计全文或首版源码快照可提高断言变更可追溯性。此缺口不改变本轮代码发现或冻结环境门槛。 |

解除 B1 阻塞必须基于修复后的工作树证据和冻结设计规定的实机结果。
