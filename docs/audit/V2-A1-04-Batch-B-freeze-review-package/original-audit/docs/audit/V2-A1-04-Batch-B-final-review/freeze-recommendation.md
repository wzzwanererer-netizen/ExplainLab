**C · BLOCKED**

当前设计有八项 P1 冻结阻塞。B1 要建立的 PG 会话拓扑、SQLite 保护时序和存储路径边界在候选中仍不确定，直接实现会固化需要返工的公共接口。后续阶段的 Active 归档、ZIP 附件归属、staging 生命周期、审核决议及 GC 恢复也存在已经能从设计和基线代码推演出的状态错误。

| 修订面 | 冻结复审判定标准 |
|---|---|
| B1 的公共契约 · F06、F07、F08 | PG 多 key 连接归属与物理锁顺序明确，部署继续使用单 Backend/单数据根。D23 恢复先完成并关闭事务，再取附件锁。SQLite 文件操作时点与 R1.3 一致或有明确受控裁决。正式根、staging、quarantine 与身份数据路径互不误扫。 |
| 审核与导入 · F01、F02、F04 | 每个 ZIP 附件有确定目标与 staging 所有权，幂等路径避免吞掉变化的附件集合。所有新增路径在条目写前能保证 archived 约束。approve/reject 竞争只产生一个有效决议，坏 envelope 仍可退出。 |
| 恢复 · F03、F05 | staging 的生产、提交、清扫共享保护区间。GC/ORP 定义重复任务、两份副本、move 后 DB 记录前崩溃、无任务及终态残留的收敛条件。删除或恢复前可核验引用、租约、hash 和时间。 |
| 验收映射 | 在已有 53 个编号中补上足以证明上述修订的具体时序，并映射继承的 R1 验收。最终实现验收再取得真实 PG、SQLite、Windows、POSIX 与故障注入证据。 |
