# 05 · 风险登记（P0–P3）

- 分级：P0 = 数据丢失/安全阻断；P1 = 核心契约/身份风险；P2 = 本地可靠性/验证缺口；P3 = 非阻断改进。
- 每条均区分**事实**（有代码/测试/命令证据）与**推测**（未验证的部署/故障假设）。
- “阻断 Batch A”按当前支持范围（Windows + SQLite + 单进程）判断；不把生产部署前置条件混同于本批功能冻结。

## P1

### R-P1-01 · 跨进程身份互斥仅靠单实例 ProcessLock

- **事实**：`identity_guard` 使用 `threading.RLock`（`source_identity.py:585`），只保证进程内线程互斥；应用启动时 `ProcessLock` 独占 `data_dir`（`main.py:72–91`）。
- **风险**：若以多 worker/多实例共享同一 `data_dir` 运行，导入与 MATERIALIZE 可跨进程交错，重新出现 §22.2 冲突窗口。
- **推测**：第二个 worker 会因 ProcessLock 失败而无法启动；未实测。
- **测试**：单进程冲突/并发测试通过；无跨进程竞争测试。
- **未验证**：多 worker、reload 交接、外部 CLI 同时写。
- **阻断 Batch A**：否（单进程是当前支持模型）。
- **可延后**：是，但必须在部署文档中明确“单实例”约束；若未来多 worker，需 DB 级锁/文件锁。

### R-P1-02 · PostgreSQL 完全未验证

- **事实**：无 PG 实例/容器/客户端；`EXPLAINLAB_PG_TEST_URL` 未设置；178 项 PG 门控测试 skipped。
- **风险**：迁移 up/down、tsvector/触发器/级联、CJK 回退、向量/混合检索在部署目标上可能有差异。
- **测试**：SQLite 全绿；PG 零执行。
- **未验证**：所有 PG 路径。
- **阻断 Batch A**：不阻断 SQLite 开发验收；**阻断“可上 PostgreSQL 生产”的声明**。
- **可延后**：否，若部署目标为 PG，应在进入生产前补齐。

### R-P1-03 · POSIX 完整事务未验证

- **事实**：WSL 探针 9 项 PASS，但完整 Journal/导入因缺 pip/SQLAlchemy 无法运行。
- **风险**：Linux 部署下目录 fsync/权限/锁行为与 Windows 不同，完整链路可能暴露新问题。
- **测试**：仅原语级探针。
- **未验证**：POSIX 全量套件、Journal 恢复、SQLite 事务。
- **阻断 Batch A**：否（当前验收环境 Windows）。
- **可延后**：否，若计划 Linux 部署。

### R-P1-04 · 断电/真实 I/O 错误下的持久性未验证

- **事实**：Windows 目录 fsync 为 no-op；故障注入是 Python 层替换，不是真实 EIO/ENOSPC/断电。
- **风险**：崩溃后可能出现“DB 已提交但 Journal 未归档”或“ID 已换但记录未提交”；设计有恢复门，但未在真实断电下演练。
- **测试**：PREPARED/COMMITTED 恢复分支、fsync/close/replace 异常均覆盖。
- **未验证**：kill -9、断电、磁盘满、只读文件系统。
- **阻断 Batch A**：否；阻断“掉电安全”宣传。
- **可延后**：可，但应保留 best-effort 表述。

## P2

### R-P2-01 · 审核批准第二次 commit 与索引同步非原子

- **事实**：`governance.approve_review` 第一次 commit（审核 + 导入字段，470），随后 `_sync_applied_action` + 第二次 commit（471–476）。
- **风险**：第二次失败时审核/身份已落库、索引可能滞后；返回 5xx 但审核已生效。
- **测试**：正常路径通过；无第二次 commit 失败注入。
- **未验证**：索引失败后的补偿/重试。
- **阻断 Batch A**：否（不制造身份冲突）。
- **可延后**：是；可增加索引重建/重试任务。

### R-P2-02 · 状态 4 使整次 ROTATE 失败

- **事实**：`rotate()` 遇到任一状态 4 抛 `SOURCE_IDENTITY_INCONSISTENT`（963–967）。
- **风险**：一条孤儿/异常文档会阻断全库轮换，需要人工修复。
- **测试**：`test_rotate_blocks_on_state_4` 证明不换 ID。
- **未验证**：运维修复流程。
- **阻断 Batch A**：否（fail-closed 是设计选择）。
- **可延后**：是；可提供诊断/修复 CLI（本批不交付）。

### R-P2-03 · Journal 损坏会全局阻断身份操作

- **事实**：恢复/归档/校验失败抛 `JOURNAL_CORRUPT` 或 `SOURCE_IDENTITY_INCONSISTENT`；导入、审核、导出、ROTATE 都先过恢复门。
- **风险**：单文件损坏导致导入/导出不可用（可用性，不是静默错误）。
- **测试**：损坏 current、checksum 不匹配、归档损坏均 fail-closed。
- **未验证**：真实磁盘损坏后的恢复工具。
- **阻断 Batch A**：否（fail-closed 优于猜测）。
- **可延后**：是；需备份/修复手册。

### R-P2-04 · 已物化条目完全拒绝再导入

- **事实**：`markdown._apply_import` 与审核钩子对 `has_committed_materialize` 直接 409。
- **风险**：用户无法用 Markdown 更新已物化本地文档；这是产品行为，不是数据损坏。
- **测试**：7 项冲突测试锁定。
- **未验证**：后续产品需求（是否允许受控更新）。
- **阻断 Batch A**：否。
- **可延后**：是；需新设计（版本/合并策略）。

### R-P2-05 · Uvicorn reload / 多 worker 未实测

- **事实**：ProcessLock 在启动时获取；reload 会重启进程。
- **风险**：旧进程未及时释放或新进程启动时序问题；多 worker 预计不可用。
- **测试**：无。
- **未验证**：真实 `--reload`、`--workers 2`。
- **阻断 Batch A**：否（开发脚本为单进程）。
- **可延后**：是；部署文档需禁止多 worker。

### R-P2-06 · Windows 文件占用（sharing violation）未验证

- **事实**：Windows 上被占用文件无法 rename/delete；本批未注入。
- **风险**：ID/Journal 发布在杀毒/索引器占用时可能短暂失败，触发异常而非静默损坏。
- **测试**：replace/close 异常注入，但不是 Windows sharing violation。
- **未验证**：真实占用场景、重试策略（本批无重试）。
- **阻断 Batch A**：否。
- **可延后**：是。
